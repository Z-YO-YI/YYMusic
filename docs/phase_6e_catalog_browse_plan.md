# Phase 6E — 音乐库浏览查询基础

2026-09-06，基于已 fetch/pull 的 `40fb7a6`，开发分支 `codex/catalog-browse-data`。
再次校验 ZIP、主指令、完整 App.tsx、基础 HTML 四项 SHA-256，均与 Phase 0 一致。
按主指令 17.3 / Phase 6，先补音乐库数据合同，再独立接入原生页面。

- 独立 CatalogBrowseRepository，正式 DriftLibraryRepository 实现；普通 Library 与 Search
  接口行为保持不变。同一数据作用域导出该合同，不创建新数据库/播放器。
- 三类实体有类型安全排序：曲目名称/首位艺人/专辑/时长/首次入库时间，专辑名称/首位艺人/
  年份/曲目数，艺人名称/专辑数/曲目数。支持升降序，NULL 始终在末尾，稳定完整身份作后备顺序。
  名称只做 SQLite ASCII lower，非拼音/区域化排序；首位艺人按既有 credit.position。
- 来源类型/来源 ID 与可用性集合组合过滤；专辑/艺人按匹配曲目决定是否入选，实体计数仍是
  整个目录的既有聚合值，不伪装成筛选后的数量。过滤不依赖来源配置存在，不隐藏遗留失效引用。
- AlbumRef / ArtistRef 保留来源身份；获取单个实体、按专辑/艺人分页曲目、按艺人分页专辑。
  组合筛选必须由同一匹配曲目满足，避免多来源或多艺人关联交叉误匹配。
- 一次只读 CTE 先限制实体页再展开完整艺人，避免截断关联或数据库 N+1。分页仍用 PageRequest，
  仅取 limit+1 个实体；不同分页请求不承诺跨写入事务快照。复用合作式取消和安全失败封装。
- 排序 SQL 仅由封闭枚举映射，来源/ID/状态/分页参数绑定；只读操作不写历史、扫描文件或联网。
- 测试覆盖升降序/NULL/同名稳定分页、关联多艺人、完整来源身份、组合过滤、损坏/缺失/取消、
  单查询/零写事务、大页边界、双连接并发读与根数据合同；完整回归、格式/生成门禁与双平台 CI。

本批不改 schema/依赖/平台权限、不改既有 55 张 Golden，不实现导入/恢复、右键菜单或音乐库 UI。
不使用 WebView、生产 Fixture、音乐下载；尚不能宣称完整音乐库或应用上线。

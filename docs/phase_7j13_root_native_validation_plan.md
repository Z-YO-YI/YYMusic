## 7J13A：最小顺序循环，先独立Android入口

1. 新建独立`integration_test/root_native_repeat_poc_test.dart`，使用真实JustAudioEngine、生产PlaybackController和隔离临时SQLite仓库；只生成确定性低幅WAV和测试曲目，不读取用户库/音频。数据通过既有Repository接口建立，源解析只把本探针生成的文件交给既有PlayableSource。
2. 两项队列、RepeatMode.all，通过根playNativeSequence开始；仅观察自然原生事件和根通知，验证q0→q1→q0及相应cycle/位置进度，根元数据和持久化currentEntryId同步。不得人工emit原生事件、用seek/下一曲伪装自然完成或仅凭固定sleep判成功。
3. 根历史必须由真实时钟前进确认，使用真实仓库观察；重复TrackRef在“最近播放”中去重是既有合同，不能错误要求重复行。跨轮应更新该曲的听取记录身份，单纯play确认不能记历史。
4. 在新轮首项通过根关闭自动继续，观察截尾后本项完成且无后续自然重启；根关闭排空后重建根，只恢复持久化队列、不自动播放。所有等待和资源释放有界，旧根/引擎/仓库和探针自身临时文件按所有权清理。
5. 新增严格的脱敏结果合同及反例测试：精确源码SHA、平台、测试数量、条目/轮次/进度、队列/历史/停止/恢复/关闭事实，失败/缺项/跳过不能通过，明确acousticGapMeasured=false。指标必须来自断言过的观测，不手填未执行成功。
6. 新增默认关闭且仅允许显式Android诊断的新输入，保持现有单源、HTTPS和引擎序列探针的入口、计数、Windows Profile身份验证不变；生产main不引用探针，不产生发布。对应Node门禁和Dart合同测试先行，再执行格式、分析、全量回归、同SHA GitHub构建与Android模拟器实测。

准备新增：独立根探针、结果合同/单测、工具门禁、阶段报告和ADR；准备修改：仅显式工作流选项及阶段索引。生产代码只有发现可复现缺陷时才按失败回归最小修复。风险是把根尚未提交的原生事件误当持久化成功、历史去重误判、关闭与后台补充竞争，以及诊断入口污染普通包。

# Phase 7J7：播放地址有效期保护

## 基线

Z-YO-YI/YYMusic，基线5489b5c，fetch/ff-only pull确认远程最新后创建codex/source-expiry-guards。上轮Phase7J6有界前瞻已提交并同步，仍属有效进展。本轮为共享Android/Windows播放核心补充失效地址边界，不改变UI或提前开放无缝开关。

## 实现与边界

- PlayableSource.networkStream新增可选expiresAt，归一UTC；isValidAt由调用方传入时间，精确到期即失效。local/content源没有期限。期限不进入Track、队列、数据库、日志或toString；地址和headers继续脱敏。未提供期限不是永久有效的保证。
- 首次解析和调用load之前均复核。失效结果重取一次，若仍失效使用既有streamUrlExpired安全错误，不无限重试。重取后再次核对完整TrackRef、dispose及canPlay。队列保存、停止旧播放器和初始尾部解析耗时后，当前地址若已失效也会重取。初始原生批次重新绑定实际要加载的首项，元数据和cursor仍在同一根。
- 引擎在串行load/loadSequence/appendSequence实际执行时检查期限，已失效输入在任何状态替换/原生调用之前拒绝，原批次不被预检失败破坏。可注入时钟用于确定性测试，生产默认系统时间。
- 带明确期限的未来曲目暂不进入初始或追加预载，留在应用队列中；真正到达它时走既有逐项解析路径。缺少定时撤销机制时，不推测播放速率、暂停时长和原生打开时机以保证未来地址有效。

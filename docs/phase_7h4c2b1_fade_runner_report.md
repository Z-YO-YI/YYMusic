# Phase 7H4C2b1：可取消淡出执行器

本批在根音量隔离之后实现异步执行器，**尚未绑定PlaybackController到期路径，实际淡出仍未启用**。继续H4C2b2根接线，不将独立时序通过当成实机听感通过。无UI/依赖/schema变更。

## 实现与所有权

SleepFadeRunner借用writeGain、pause、restore、isCurrent四种根回调，不持有引擎，不保存用户音量。start在所有外部回调前注册唯一Future，可重复调用；cancel撤销等待，close取消后等待在途命令及恢复。

默认Stopwatch计算真实经过时间，50ms建议Timer等待位于命令回调之外；慢唤醒跳过过时步骤，内部高水位防止注入时钟回拨增大振幅。每次外部时钟调用和音量写后再次验证许可。完成后只暂停一次；调用过音量写即执行finally恢复，包括写抛错但可能已改变硬件的情况。

恢复回调读取根最新用户音量，不捕获旧值；即使已取消也必须可用。执行器没有自动播放。安全结果区分completed/cancelled/failed，记录失败操作及恢复是否也失败，不保存或回显后端异常原文。调度器同步唤醒/取消时，迟到返回的Timer被取消；旧回调不能消费新等待。

## H4C2b2必须处理，不能遗漏

1. 根创建/持有唯一执行器；首次淡出即使未调过音量，也先锁定_userVolume。writeGain在每次根串行操作真正执行前重验generation/entry，计算最新用户值乘增益，不能调用公开setVolume记录成用户值。
2. 取消/新睡眠意图、暂停、切曲、停止、清空、错误与关闭撤销旧执行器。无效或过期UI动作不能意外撤销真实淡出。切曲前处理临时振幅，不能让新歌曲带着旧衰减播放。
3. restore在关闭阶段仍需可执行；禁止在当前串行操作内await执行器.close，而恢复又排队在该操作之后，造成自等待。根close应先撤销，排空命令与执行器后再由Graph释放引擎；恢复失败必须可观察。
4. 根处理最终结果仍重验generation，旧结果不能覆盖新定时。根分钟截止保持唯一到期来源，逐步Timer仅负责已到期后的短时淡出。本曲结束继续按自然完成事件消费。
5. 为既有到期测试注入可控淡出时钟/调度并保留旧取消/重入覆盖；新增真实根+FakeAudioEngine测试，不通过过滤新音量命令来维持旧断言。回归通过后才启用并进入后端设备验收。

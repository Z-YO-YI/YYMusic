# Phase 7J5：原生序列首次接入唯一播放根

## 基线与范围

基线ae46544，Z-YO-YI/YYMusic。干净工作区fetch/ff-only pull后建立codex/root-native-sequence。前轮本曲边界是有效进展，本轮按ADR136实际接到PlaybackController，未建立第二播放控制器。本批提供显式playNativeSequence供整合验证，现有生产UI/媒体回调仍使用原有入口，不能称为用户无缝开关已上线。

## 加载与根状态

- 从根捕获当前队列，拒绝排队后已过期的请求，复用现有当前曲目校验/解析/加载流程。按根顺序或随机顺序解析可播放前缀；遇到不可用尾部停止预载，保留队列引用，在实际推进时仍由既有跳过/错误记录逻辑处理。尾部错误不替换当前曲目，解析结果必须匹配完整TrackRef。
- 策略在尾部I/O期间变化时只保留首曲；原生加载期间变化时在play之前截尾。canPlay撤销不load/play/写队列。绑定只保留cursor和曲目元数据，不保留解析请求/授权headers。
- 原生cursor按批次及完整entry身份验证，未知旧批次忽略；跳跃、策略撤销后的新切曲或不一致触发安全错误和停止请求。正常相邻切曲进入同一根串行队列，先saveQueue，再在现有状态接受路径原子发布新队列、曲目和对应原生时钟，不合成零位置或用旧曲目配新时钟。
- 数据库等待期间按条目保存有界证据：首次/最近playing事实和最新状态，每项最多三份而非无界事件日志。多个已观察切曲依次持久化；真实播放进度在采用该曲目后进入原有历史记录器，避免存储等待期间播完导致漏记，也不将仅load当作有效播放。

## 策略、编辑、关闭

- 继续/随机/重复设置改变先标记边界，再排队retainSequenceThrough；本曲结束睡眠也截尾，已有待确认切曲时不接受以旧显示曲目为目标的睡眠选择。关闭继续后不启动后续曲目；已在选择之前被观察到的切曲可完成存储，再截断其尾部。
- 保留当前条目的队列编辑先截尾后保存；若已有待确认切曲则先停止再编辑，避免把旧预载当新队列。移除当前、显式重放、手动下一首回到既有单曲路径。队列持久化失败不发布错误曲目信息，安全停止并保留错误。
- 有限前缀结束返回原有自动继续/单曲重复/随机/循环/失效跳过逻辑。根关闭排空已接受存储，禁止迟到UI和play；存储已接受的物理切曲位置可被下一根恢复，恢复不自动播放。
